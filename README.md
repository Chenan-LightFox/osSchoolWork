# osSchoolWork
This is the os school work repository

---

既然这是“课程展示要求”，那你们就不能只做一个“能发消息的小系统”，而是需要：

* 架构完整
* 模块齐全
* 数据库规范
* 有协议设计
* 有工程化分层
* 展示时看起来像“真正邮件系统”

但同时：

> 你们依然应该避免实现真正 SMTP/POP3。

> 基于 HTTP 自定义协议

所以最优策略是：

# “邮件业务完整” + “协议简化”

这是课程项目最正确路线。

# 五、数据库设计（课程标准版）

这里一定要规范。

---

# 1. 用户表

```sql
user
```

字段：

| 字段          | 说明   |
| ----------- | ---- |
| id          | 用户ID |
| email       | 邮箱   |
| username    | 用户名  |
| password    | 加密密码 |
| create_time | 创建时间 |

---

# 2. 邮件表

```sql
mail
```

字段：

| 字段        | 说明   |
| --------- | ---- |
| id        | 邮件ID |
| sender_id | 发件人  |
| subject   | 主题   |
| content   | 正文   |
| send_time | 时间   |

---

# 3. 收件关系表（关键）

因为：

一封邮件：

* 多收件人
* 多状态

所以必须独立。

---

## receiver 表

| 字段          | 说明      |
| ----------- | ------- |
| mail_id     | 邮件      |
| receiver_id | 收件人     |
| is_read     | 已读      |
| deleted     | 删除      |
| folder      | 收件箱/垃圾箱 |

---

# 4. 附件表

```sql
attachment
```

字段：

| 字段        | 说明  |
| --------- | --- |
| mail_id   | 邮件  |
| file_name | 文件名 |
| file_path | 路径  |
| file_size | 大小  |
